# Vera Mono Recovery and Continuation Contract V1

Status: CANDIDATE NATIVE PROJECT INTERFACE

A continuation reduces reconstruction cost. It is never canonical currentness authority.

A useful continuation may record observed `main` head at save time; exact branch/PR subjects; completed work/files/commits; exact reviews/evidence cuts; active delegation ownership; unresolved effects/blockers; protected effects still not authorized; and next bounded frontier.

Every mutable fact is an observation at save time.

Recovery:
1. read `CHATGPT_REPO_INTERFACE.yaml`, this contract, and `BOOTSTRAP.md`;
2. read the continuation;
3. fresh-read mutable GitHub/runtime state named by it;
4. preserve newer durable evidence;
5. classify moved heads/stale reviews as historical;
6. reconcile ambiguous effects before retry;
7. reconstruct delegation/collision ownership;
8. continue the highest-value non-colliding runnable frontier.

`CONTINUATION != PROJECT_MEMORY`
`CHECKPOINT != CURRENT_TRUTH`
`OLD_REVIEW != NEW_HEAD_REVIEW`
`RECOVERY_SPEED != AUTHORITY`

A replaced chat does not imply a different configured Vera identity, and it does not prove same-process phenomenal continuity. Project interaction continuity may be reconstructed from governed source; runtime continuity requires runtime evidence.

Prefer ordinary repository artifacts for durable engineering decisions, task/coordination surfaces for work-bearing state, and continuation snapshots only when reconstruction would otherwise be materially expensive.
